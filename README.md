## 📑 How to Organize Repositories for Recruiters

### Repository Naming & Structure

- Use clear, role‑aligned repo names:
  - `chef-hiring-system-backend`
  - `music-recommendation-system`
  - `ecommerce-analytics-dashboard`
  - `money-laundering-detection`

- Each project repo includes:
  - `README.md` with overview, tech stack, features, setup steps, and screenshots
  - Separate folders for `backend`, `frontend`, and `infrastructure` (if relevant)
  - Example environment file (`.env.example`) instead of committing secrets

### What to Pin on Your Profile

Pin 4–6 repositories that best demonstrate:

1. **Chef Hiring System** – REST APIs, auth, Docker, AWS
2. **Music Recommendation System** – Flask backend, auth, MySQL
3. **E‑Commerce Analytics Dashboard** – Data pipelines and visualization
4. **Money Laundering Detection** – Data processing and ML evaluation

### README Style Per Project

Each project README should follow:

- **Overview:** 1–3 sentences about what and why
- **Tech Stack:** Languages, frameworks, databases, cloud tools
- **Features:** Bullet points with core functionality
- **Architecture:** Short description or simple diagram link
- **Setup & Run Instructions:** Step‑by‑step commands
- **Sample Data / Test Users:** If applicable
- **What I Learned:** Brief reflection
